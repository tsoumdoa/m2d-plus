# Millimetres, survey coordinates and single-view solve latency

2026-11-16; implementation worktree from v0.1.0-beta.1. Nothing committed,
pushed, installed or published. Measurements use Rhino 8.36.26296.17001,
.NET 8.0.34, Windows x64, Release, on a shared machine. They are n=1
observations, not controlled speed claims.

## Finding and remaining acceptance failures

The generated models do **not** reproduce a millimetre-dependent work explosion.
The 5,000-source block elevations take 4–7 seconds in metres, millimetres and
millimetres translated by (1e7, 1e7, 1e7). Exact fallback counts do not grow by
anything resembling 1,000 times.

An all-curved 5,000-source North elevation **does** reproduce the several-minute
Drawing stage. A live stack of our owned process locates it inside
`HiddenLineDrawing.Compute`, not a rational predicate or scheduler wait cycle.
Its metre version takes 274.806 s (249.638 s native); the mm version takes
288.373 s (267.285 s native). Both spend a long time at native progress 99%.
A same-physical-tolerance mm control (0.1 mm) takes 285.946 s, including
261.375 s native. Neither units nor the template tolerance explains this case.
The owner's unavailable model cannot be assigned this cause conclusively.

The single-view speed target is **not met generally**. A threaded native-HLD
proxy takes 156.703 s on that mm curved elevation. On the small curved-steel
fixture, the independent native ray audit costs more than HLD itself. No audit
was disabled and no certificate was relaxed to meet a timing target. The exact
analytic curved engine being developed separately is the relevant overlap.

An exploded-model plan also exposed a worker/local section archive discrepancy:
1,119 line pieces have identical bytes and both results have 364 regions, but one
region curve archive differs and the native-fragment diagnostic differs by one.
This remains a failed strict byte-equality check, not a certified equivalent run.
Section/region changes belong to the separate section agent.
The diagnostic comparison finds zero region-area delta and a largest
bidirectional sampled curve distance of 1.50e-11 m. Sampling does not prove
whole-curve equivalence or waive the raw-byte contract.

## Models and measurement method

Generated files are outside Git at `~/.t3/m2d-plus-models/mm/`:
`perf-M-blocks.3dm`, `perf-M-exploded.3dm`, `curved-perf-M-blocks.3dm`, and
`curved-steel.3dm`. The first three also have `offset-1e7/` versions.
Each file has a `.generation.json` recording its source SHA-256 and generation.
`RhinoDoc.AdjustModelUnitSystem(Millimeters, true)` scales by 1,000 about the
world origin, including block definitions/placements. The generated document
tolerance is 0.01 mm. Offset generation then translates top-level objects by
(1e7, 1e7, 1e7), without translating definition geometry a second time.

Original metre fixtures use 0.0001 m = 0.1 mm. Therefore their requested template
comparison has a tenfold physical tolerance difference. The automated timing
and topology tests use equal physical tolerances instead; document tolerance is
never silently changed in product code.

The eight views are North/South/East/West/Top/SW, a long section through the scene
centre, and the z=1.2 m plan. The offset plan is translated with the model. An
earlier offset run's absolute z=1.2 m plan is retained as evidence but excluded
from the final comparison; use `offset-blocks-corrected`.

Local wall excludes capture and archive serialization; normalization is included
on the first view. These are one-view in-process production solves with an
explicit benchmark admission budget. Capture and normalization are separate
fields. Workers use the production pool, two requested processes, automatic
memory caps, exact runtime/engine handshake, and one cold eight-view batch.
The coordinator does not initialize Rhino, so two workers remain within the
two-owned-Rhino-process limit. No unrelated Rhino process was attached or changed.

**Native yardstick:** `HiddenLineDrawing.Compute`, not the `_Make2D` command.
Use hidden curves on, tangents/seams off, parallel projection, and document
tolerance. Tables quote the native compute phase alone, excluding adapter output
and audits. The curved-steel raw proxy adds all prepared sources directly. The
threaded curved-M control is labelled separately: production threading remains
off because its deterministic-output contract was not changed.

Raw evidence is `~/.t3/m2d-plus-models/evidence/unit-scale/`: `profile`, `before`,
`curved-priority`, `native-threaded-mm-curved`, `after`, and `final`. Each final
scene has the complete Info/phase records in `scale.json`, detached scene and
request archives, and local/worker drawing archives and hashes. `measurements.md`
and `phases.csv` are generated by `tools/worker-bench/scale-report.py`.
The benchmark continues to record failed hash comparisons and returns nonzero.

## Progress, cancellation and correctness

Long phases now report plain-language status inside the solve, work counts where
available, and elapsed seconds. The native progress callback is connected.
An approximately 1 Hz heartbeat keeps an unchanging native percentage explicit;
it does not pretend native work has advanced. Events are throttled to 10 Hz.
Workers stream progress frames through the existing pipe; writes are serialized.
Child completion never marks the whole batch complete. Generation/publication,
leases, Job Objects and actual-native-release rules are unchanged.

Managed budgets are deterministic, not elapsed-time cutoffs, so scheduling and
machine load cannot select which spans receive confidence. Native intersection
calls themselves are not preemptible managed operations. Hard kill remains a
worker capability, not a new promise about local HLD.

The new native cancellation regression cancels a real mm elevation from inside
its native progress callback. Return/release latency is 7.1 ms on .NET 8 and
9.2 ms on .NET 10 in this control. This is evidence for cooperative cancellation,
not a bound on every Rhino native call. The existing blocked-worker hard-kill,
document-close publication rejection and request-deadline tests also pass.

## Verification and integration overlap

Debug and Release: zero warnings/errors. Forced local hook passes.
`Test-WalkingSkeleton.ps1` runs both runtimes in process-cap-compatible groups:
343 Core, 62 UI-model and 234 distinct licensed Rhino tests pass per runtime.
The new Core timing guard uses alternating m/mm order, warm-up and five-run
medians, plus a 20 ms timer reserve: measured ratios are 1.011 (.NET 8) and .963
(.NET 10). Topology/classes are checked against the unchanged rational oracle;
Rhino integration compares four elevations at equal physical tolerance in m,
mm and mm at 1e6/1e7 offsets. Same-source/same-class collinear intervals are
joined before topology comparison; partition boundaries need not be identical.

Six existing tests were not run because they instantiate a Rhino test host plus
two workers, exceeding the owner's two-process limit: persistent parallel worker
equality, crash sibling recovery, startup-timeout sibling recovery, isolated
memory retry, no-retry-headroom sibling preservation, and worker presentation
equality. The separate no-Rhino coordinator runs actual two-worker measurements
and reports strict hashes, including failures. Do not call this an unfiltered
full-suite pass. Logs are `artifacts-scale-*.log`; archived evidence stays outside
Git. Two-worker results and complete per-view phases are in `measurements.md`.

Overlap: `ComposedVisibility` (instrumentation, native viewport and conservative
work limits) overlaps Fable's hook and the section agent's quarantine work;
`SectionDrawing` changes only its native viewport/progress call.
`DrawingComponent.Async.cs` changes one message-line expression to display the
new phase detail, overlapping Opus's status work. Capture/settings reuse and
analytic curved visibility were not implemented here.
