M2D+ Drawing: Grasshopper UX mockup

One component and five inputs, of which only View is required. Revision 4 applies the owner’s decision on views: a referenced planar surface becomes an editable M2D+ view box in Rhino (right-click Validate views), per-view settings are m2d.* Attribute User Text on it, and a new Depth input drives plane and rectangle views. The settings editor is gone. Revision 3 still holds: cut fill from Rhino 8 section styles, else the object’s colour; scale picks line weights only.

1 · On the canvas

Typical setup: a clipping plane name in View, nothing in Geometry (the whole visible model) and no Target (the drawing is shown in place). The component is done, and Bake sits on its message tab. Five inputs (Depth is new in revision 4, appended last), nine outputs.

Inputs: G Geometry · V View · T Target · S Settings · D Depth. Outputs: V Visible · H Hidden · B Beyond · Fc Far clip · C Cut · Ha Hatch · ? Unresolved · F Frame · i Info. Trees are always {view; source path}.

2 · View objects: a surface becomes a view box new

The view is a Rhino object you edit. Reference a planar surface (or a closed rectangle) in View, right-click Validate views, and M2D+ converts it in place into an M2D+ view box: an extrusion whose front face is the view frame (and the cut plane) and whose length is the depth. Same object, same id, one undo. Drag its back face with the gumball to change the depth; its per-view settings are m2d.* keys in Rhino’s Properties ▸ Attribute User Text. Try the controls: they drive the view-range diagrams in section 3.

Who wins, per key and per view

  1. 1Depth input (depth only)One value for all views or one per view: a slider for plane and rectangle views. A box or view box always uses its own length, with a remark.
  2. 2Settings input, when wiredOnly the keys it contains. One branch = all views; one branch per view, or [M2D View 01] headers.
  3. 3The view objectm2d.* user text on the view box or clipping plane. default = not set here.
  4. 4Menu defaultsThe right-click toggles, stored on the component, for every view.
  5. 5Built-in defaultUsually Auto: inferred from the source (scene extent, clipping-plane depth).

Scale = line weights (Revit’s View Scale)

Nothing gets smaller. The drawing is always made 1:1 in the model and placed 1:1 on Target. scale only chooses which column of print widths (mm) is used on bake and print. Preview widths on the canvas stay fixed per class.

In-between scales take the nearest band on a log scale: up to 1:70 → 1:20–1:50, 1:71–1:141 → 1:100, from 1:142 → 1:200–1:500. So 1:75 → 1:100, 1:150 and 1:1000 → 1:200–1:500.

For a sheet: show the 1:1 bake in a Rhino Layout detail at 1:100, or add a GH Scale (0.01 about the target origin). weights = layers uses the source layers’ print widths instead.

3 · View range: depth, far clipping, beyond and depth cueing new

Measured from the view plane along the view direction, as in Revit. Beyond is a line class (Revit’s Bottom and <Beyond> line style). Depth cueing is a graphic ramp on top of any class, from Start to End (percent of depth) down to the Fade limit. Far clip decides what happens at the depth plane.

4 · Rectangle views, placed 1:1 new

The rectangle’s plane is the view plane (you look along its −Z). It cuts the building, so the drawing is a section; moved outside, the same rectangle gives an elevation. Its size is the crop; depth sets how far back you see. With a Target, the rectangle’s own plane is moved onto the target plane: Frame = the rectangle, moved and rotated, always 1:1. scale never shrinks the drawing; it only picks line weights.

View[0] = the rectangle → Target[0] = a horizontal plane. A point at (u, v) on the rectangle lands at (u, v) on the target. No Target: the drawing lies on the rectangle itself.

The anchor frame of each source

Rectangleits own plane: origin and X/Y axes. Frame = the rectangle.
Planethe plane. Frame = scene bounds on it.
Boxits plane, moved to the +Z (cut) face. Depth = its height.
Clipping planeits own plane (never mirrored).
Named viewcamera target, camera right/up.
Vector, Top, SW…world origin projected; Z = 0 is the level line.

One Target, several views: a row along the target’s X; anchors keep their height, so put each section rectangle’s origin on the ground level and the sections line up. N targets: View[i] → Target[i]. Placement never scales: for a 1:100 sheet use a Rhino Layout detail, or a GH Scale after M2D+.

5 · Section styles and cut fill revised

Deterministic, never guessed: for each cut object, Rhino 8’s own SectionAttributesSource picks one style. A missing style falls to the next row, ending at a solid fill in the object’s display colour. M2D+ has no hatch presets or style editor of its own. The hatch setting can override all of it.

Which style (per cut object)

  1. 1By clipping plane and the view is a Rhino clipping plane with its own styleFromSectioner → the clipping plane’s Attributes.GetCustomSectionStyle()
  2. 2By objectFromObject → the object’s Attributes.GetCustomSectionStyle()
  3. 3By parent (inside a block)FromParent → the block instance’s resolved style, up the nesting
  4. 4By layer (Rhino’s default)FromLayer → Layer.GetCustomSectionStyle()
  5. 5No style: solid fill in the object’s display colourAttributes.DrawColor(doc): the layer colour unless the object overrides it (by object, material or parent, as Rhino resolves it). Plain GH geometry has no colour and fills in ink.

RhinoCommon 8 has no document section-style table and no “clipping plane overrides everything” flag; the first engine spike checks rule 1 against the viewport with a fixture.

6 · Runtime states

The message tab holds one short line. While a job runs, a cobalt progress line runs along the body. The outputs only ever hold a complete result for the current inputs.
